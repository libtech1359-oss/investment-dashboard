  1. システム概要
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  PC常時稼働のDiscord botで、投資判断を補助するマルチエージェントAIシステム。
  外出先からスマホで指示を出せる。

  【構成イメージ】
  CEO（あなた）
    └─ Discord #ai秘書チャンネル
         └─ 秘書室長 AI（secretary.js）
              ├─ 市場分析部
              ├─ ポートフォリオ管理部
              ├─ リスク管理部
              ├─ 反対意見部（Devil's Advocate）
              └─ 監査部
                   └─ 最終レポート → Discord返信

  【使用技術】
  - Node.js + discord.js v14
  - Ollama（ローカルLLM: gemma4）
  - Google Apps Script（スプレッドシートからデータ取得）
  - SQLite（長期記憶）
  - node-cron（定時実行）

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  【自動起動】
  PC起動時に自動スタートする設定済み。
  スタートアップ経由: start_ai_secretary.bat → VBScript

  【手動起動】
  D:\AI\ai-corp> node index.js

  【手動停止】
  ターミナルで Ctrl+C

  【再起動が必要なタイミング】
  - index.js / secretary.js / agents/*.js を変更したとき
  - .env を変更したとき
  - node_modules を更新したとき（npm install後）

  【コマンド再登録が必要なタイミング】
  スラッシュコマンドを追加・変更したとき:
  D:\AI\ai-corp> node register.js

  3. AI部署構成（エージェント）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ┌─────────────────┬────────────────────────────────────────────────┐
  │ 部署名          │ 役割                                           │
  ├─────────────────┼────────────────────────────────────────────────┤
  │ 秘書室長        │ タスク分解・全部署への指示・最終統合            │
  │ マーケット分析部│ 指数・為替・コモディティ・暗号資産の動向分析    │
  │ ポートフォリオ  │ 保有銘柄評価・アロケーション・NISA活用         │
  │ リスク管理部    │ VIX・ドローダウン・集中リスクの定量評価        │
  │ 反対意見部      │ 他3部署の楽観分析に意図的に反論・最悪シナリオ  │
  │ 監査部          │ 6項目審査（方針違反/幻覚/矛盾/数値/履歴/過信） │
  └─────────────────┴────────────────────────────────────────────────┘

  【新部署の追加方法】
  1. agents/ フォルダに新ファイルを作成（analyze(context) を実装）
  2. secretary.js の AGENTS 配列に require('./agents/新部署') を追加
  3. DEPT_KEY に日本語名→キー名のマッピングを追加
  ※ これだけで自動的にパイプラインに組み込まれる

  4. 分析パイプライン
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  CEO指示
    ↓ task_id 採番（例: task-20260531-001）
  Step 1: GASデータ取得 + 長期記憶参照
    ↓
  Step 2: 秘書がブリーフィング文生成（300字以内）
    ↓
  Step 3: 市場/ポートフォリオ/リスク 並列分析
    ↓

    ↓
  Step 4: 監査部 6項目審査 → 承認/条件付き承認/要見直し
    ↓
  Step 5: 最終統合レポート生成
    ↓
  Discord返信 + タスクドキュメント保存

  【タスクドキュメント】
  各ステップの結果が data/tasks/task-20260531-001.json に逐次書き込まれる。
  途中でクラッシュしても完了済みステップのデータは残る。

  5. Discordコマンド一覧
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  【マーケット・投資】
  /market          現在の市場データ（NASDAQ/S&P500/ゴールド/BTC/F&G）
  /portfolio       ポートフォリオ概要（評価額・含み益・収益率）
  /trades          直近の取引履歴（口座絞り込み可）
  /buy             ATH比較と買い判断（-30%以上:強い買い 〜 0%以上:最高値圏）
  /nisa            特定口座からNISA移行候補を表示
  /rules           投資ルール確認（現金残高を入力して余剰計算）

  【記憶・プロファイル】
  /profile show    CEOプロファイル（構造化方針）を表示
  /profile set     プロファイル項目を設定（リスク許容度/VIX上限/F&G買いゾーン等）
  /remember        方針・ルール・メモを長期記憶（SQLite）に保存
  /memory          長期記憶の一覧表示
  /forget          長期記憶から特定IDを削除

  【ログ・履歴】
  /log             AI秘書のセッションログを参照
                   ステップ指定: summary / data / decompose / market /
                                 portfolio / risk / audit / report
                   日付指定: 例 2026-05-31
                   番号指定: 今日の何番目か（省略で最新）

  【システム管理】
  /halt            緊急停止（即時・確認なし）
  /resume          自動取引再開（確認ボタンあり・30秒タイムアウト）
  /status          現在のシステム状態表示（system_state.json の中身）
  /events          halt/resume/audit_override のイベント履歴

  【AI秘書（テキスト）】
  #ai秘書チャンネルに日本語で話しかける
  例:「今日の市場どう？」「ポートフォリオ全体の状況を教えて」
  → 全部署が並列分析 → 最終レポートが返ってくる

  6. スケジューラー（自律実行）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  bot起動と同時にスケジューラーも起動する。

  【定時実行】
  07:00 JST（月〜金）  朝の市場分析
  12:00 JST（月〜金）  昼のポートフォリオ確認

  【イベント監視】
  5分ごとにNASDAQをチェック。
  前日比 -3.0% 以下を検知したら緊急監査を自動実行（1日1回）。

  【停止中の動作】
  system_state.json の trading_enabled が false のとき:
  → 定時実行・急落監視ともにスキップ（ログに「スキップ（停止中）」と記録）

  【スケジュール変更方法】
  scheduler.js の SCHEDULES 配列を編集してbotを再起動。
  例: 夜間レポートを追加する場合
    { name: '引けレポート', icon: '🌙', cron: '0 16 * * 1-5',
      instruction: '本日の引け後の状況と明日の戦略を報告してください。' }

  【NASDAQ急落閾値の変更】
  .env に追記:
    CRASH_THRESHOLD=-5.0   ← -5%に変更する場合

  【レポート先チャンネルの変更】
  .env に追記:
    REPORT_CHANNEL=定期レポート   ← チャンネル名

  7. 緊急停止スイッチ
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  【基本思想】
  system_state.json の trading_enabled が唯一の真実。
  このファイルを見れば現在の状態が即わかる。
  botが落ちても、ファイルが残っていれば安全。

  【停止方法 3通り】
  (1) Discord: /halt コマンド（最速・推奨）
  (2) ファイル直接編集: trading_enabled を false に書き換え→保存
  (3) bot停止: node プロセスを Ctrl+C で終了

  【再開方法】
  (1) Discord: /resume → 確認ボタンを押す
  (2) ファイル直接編集: trading_enabled を true に書き換え→保存

  【system_state.json の内容例】
  {
    "trading_enabled": false,       ← false=停止 / true=稼働
    "halt_reason": "manual_stop",   ← 停止理由
    "halted_by": "CEO",             ← 実行者
    "halted_at": "2026-05-31T..."   ← 停止日時
  }

  【halt_reason の種類】
  manual_stop     : /halt コマンドまたは手動
  crash_detected  : NASDAQ急落モニター（将来実装）
  audit_override  : 監査部による強制停止（将来実装）

  【安全設計】
  ・デフォルト: false（インストール直後から停止状態）
  ・ファイルが存在しない → false（停止）
  ・ファイルが破損している → false（停止）
  ・trading_enabled が true 以外の値 → false（停止）
  ※ どんな異常時も必ず停止側に倒れる設計

  【イベント履歴の確認】
  data/event_log.jsonl に全halt/resumeが記録される。
  Discord: /events コマンドで最新10件を表示。

  8. タスクID管理
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  CEO指示を出すたびに自動で task_id が発行される。
  形式: task-YYYYMMDD-NNN（例: task-20260531-001）

  この1つのIDで以下がすべて紐づく:
  ・data/tasks/task-20260531-001.json  ← タスクドキュメント（全部署の結果）
  ・logs/YYYY-MM-DD.jsonl              ← セッションログ（処理時間等）
  ・logs/secretary/YYYY-MM-DD.log     ← 秘書テキストログ
  ・logs/market/YYYY-MM-DD.log        ← 各部署テキストログ
  ・memory.db の decisions テーブル   ← 長期記憶

  【タスクドキュメントの中身】
  {
    "id": "task-20260531-001",
    "status": "completed",
    "secretary":    { "briefing": "...", "elapsedMs": 1200 },
    "market":       { "content": "...", "elapsedMs": 4500 },
    "portfolio":    { "content": "...", "elapsedMs": 3200 },
    "risk":         { "content": "...", "elapsedMs": 3800 },
    "devil":        { "content": "...", "elapsedMs": 3100 },
    "audit":        { "verdict": "承認", "elapsedMs": 2100 },
    "final_report": "## 📊 AI Capital 投資レポート..."
  }

  Discord返信の末尾に `📋 task-20260531-001` が表示される。
  この番号をメモしておくと後でログ参照できる。

  【botがオフラインのとき】
  原因候補（優先順）:
  1. Ollamaが起動していない → ollama serve を実行
  2. node_modules がない → npm install を実行
  3. .env が正しくない → DISCORD_TOKEN / GAS_URL を確認
  4. PCが再起動されてbatが起動しなかった → 手動で node index.js

  【返答が遅い・タイムアウトする】
  原因候補:
  1. Ollamaのモデルロードに時間がかかっている（初回は遅い）
  2. GASのレスポンスが遅い → GAS側のトリガーを確認
  3. 複数部署が並列実行中にCPUが詰まっている → 軽いモデルに変更検討

  【スラッシュコマンドが出てこない】
  → node register.js を実行（数秒で反映）

  【スケジューラーが動かない】
  確認手順:
  1. /status で trading_enabled を確認
  2. logs/scheduler/ のテキストログを確認
  3. bot再起動後にログに「スケジューラー起動完了」が出るか確認

  【ポートフォリオデータが取得できない】
  1. GAS_URLが正しいか確認
  2. GASウェブアプリが「全員」に公開されているか確認
  3. ブラウザで GAS_URL に直接アクセスしてJSONが返るか確認
